# SIMDEC 3 — Тренажер управлінських рішень

Кафедра економіки та публічного управління ННІПСМ ДонДУВС.

Третя версія працює без React і без збирання: GitHub Pages показує файли так, як вони лежать у репозиторії.

## Що де лежить

| Файл | Призначення |
|---|---|
| `index.html` | тренажер для здобувачів |
| `editor.html` | редактор кейсів (для викладачів) |
| `data/simdec-data.js` | **увесь зміст**: налаштування, описи моделей, етапи, кейси |
| `assets/` | оформлення, скрипти, зображення |

Код у `assets/js` під час роботи з кейсами змінювати не потрібно.

## Як додати або виправити кейс

Редактор: `…/editor.html`. Усе, що ви змінюєте, спершу зберігається як чернетка у вашому браузері, а на сайт потрапляє лише після кнопки «Опублікувати».

**У формі.** Ліворуч оберіть кейс або «+ Новий кейс», заповніть поля, позначте правильний варіант, натисніть «Переглянути», щоб пройти кейс, потім «Опублікувати».

**З текстового файлу (як у Moodle).** Натисніть «Імпорт кейсу» → «Завантажити шаблон кейсу», напишіть кейс у Word чи Блокноті, збережіть як `.txt` або `.docx`, завантажте файл → «Розпізнати» → «Додати до тренажера» → «Опублікувати». Будь-який наявний кейс можна вивантажити в такому ж форматі кнопкою «Зберегти як текст».

Коротко про формат:

```
МОДЕЛЬ: OODA
НАЗВА: Назва кейсу
ВВІДНА:
Текст ввідної, абзаци через порожній рядок.

ЕТАП: OBSERVE
ПИТАННЯ:
Ситуація на етапі та питання.

+ Правильний варіант
> Пояснення
- Хибний варіант
> Пояснення
```

## Публікація і доступ

Змінювати сайт може лише той, хто має ключ доступу GitHub (fine-grained token з правом Contents: Read and write лише на цей репозиторій). Ключ вводиться один раз на сторінці «Публікація на сайті» і зберігається тільки в браузері. Відкрити редактор може будь-хто, але без ключа він не здатен нічого опублікувати. Якщо ключ втрачено або скомпрометовано, видаліть його на GitHub (Settings → Developer settings → Fine-grained tokens) і створіть новий.

Запасний спосіб без ключа: меню «Ще» → «Завантажити simdec-data.js» і завантажити файл у папку `data` репозиторію через Add file → Upload files.

## Результати

Після завершення кейсу здобувач натискає «Надіслати результат викладачеві». У Google Apps Script надсилаються ті самі поля, що й у версії 2: `name`, `date`, `result`, `percent`, `model` (наприклад, `OODA (Кейс 3)`), тому таблиця працює без змін. Адресу скрипта можна змінити в редакторі → «Загальні налаштування».

## Публікація на GitHub Pages

Settings → Pages → Build and deployment → Source: **Deploy from a branch**, Branch: **main**, папка **/ (root)**.
